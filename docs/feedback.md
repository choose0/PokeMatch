# 4단계: 시험 기록

## 시험 방법

- randomuser.me(무료 인물 사진 사이트)에서 남녀 각 5장씩, 총 10장의 얼굴 사진을 받아왔다.
- 매번 브라우저를 열어 손으로 테스트하면 느리므로, `public/matcher.js`와 **완전히 같은 계산식**(정규화·내적·가중치·색 판정)을 그대로 옮긴 임시 스크립트를 Node.js로 만들어 10장을 한 번에 돌렸다. (이 스크립트는 시험용이라 저장소에는 올리지 않았다)
- "걸린 시간"은 CLIP 이미지 벡터 계산 + 151마리 점수 계산에 걸린 시간만 잰 것이다. 실제 브라우저에서는 처음 한 번 모델을 내려받는 시간이 따로 더 걸린다(3단계의 진행률 표시가 그 시간을 보여준다).

### 문제 정리 (모델 / 데이터 / 점수 공식 / 화면 중 어디 문제인가)

1. **점수 공식 문제 — 닮은 정도가 항상 100%.**
   실제 최종 점수는 0.21~0.45 사이로 나오는데, `SIMILARITY_MAX`가 0.35라서 점수가 조금만 높아도 전부 100%로 잘린다. 10장 모두 100%로 나오니 숫자에 아무 의미가 없다.
2. **점수 공식(색 판정) 문제 — 몇몇 포켓몬(코일·레어코일)에 결과가 몰림.**
   1위 점수를 색/그림/설명 점수로 나눠 보니, 색 점수는 10장 중 10장 모두 `color=1`(사진 색 = 포켓몬 색)이었다. 색 판정이 사진 가운데 60% 영역을 보는데, 얼굴이 작게 나온 사진은 이 영역에 회색 스튜디오 배경이 많이 포함돼 "회색"으로 잘못 판정되고, 그 결과 회색 포켓몬(코일 계열)이 항상 유리해졌다.

## 적용한 수정

| 무엇을 | 원래 값 → 새 값 | 왜 |
|---|---|---|
| `SIMILARITY_MIN` / `MAX` | 0.15~0.35 → 0.2~0.42 | 10장을 시험해서 실제 최종 점수 분포(최소 0.21, 평균 0.25~0.32, 최대 0.45)를 확인하고, 그 범위에 맞춰 다시 잡았다. 이제 73~100% 사이로 값이 퍼져서 "닮은 정도" 숫자가 실제로 의미를 가진다. |
| 색 판정 범위 | 가운데 60% → 35% | 얼굴 중심으로 더 좁혀서, 인물 사진 뒤 배경(특히 회색 스튜디오 배경)이 색 판정에 끼치는 영향을 줄였다. |

가중치(0.5 / 0.4 / 0.1)는 그대로 두었다. 텍스트 가중치를 0.6으로 올려서도 같은 10장으로 시험해 봤지만 결과가 크게 나아지지 않아서, 코드를 더 복잡하게 만들 이유가 없다고 판단해 원래 값을 유지했다.

**해보고 채택하지 않은 것**: 포켓몬 151마리 벡터의 평균을 구해서 빼주는 "센터링" 보정도 실험해 봤다(같은 스크립트로 비교). 일부 사진에서는 결과가 더 다양해졌지만 회색 배경 사진에서는 효과가 크지 않았고, `data/pokemon.json`에 새 필드를 추가하고 `matcher.js` 로직도 복잡해져야 해서 이번 단계에서는 적용하지 않았다. 색 판정 범위를 좁히는 것만으로도 충분히 개선됐다.

## 남은 문제와 원인 구분

- **여전히 남은 문제**: 회색 배경 사진 3장(men-1, women-1, women-2)은 색 범위를 좁혀도 코일 계열로 쏠린다. 색 점수 분해표를 보면 이 사진들은 그림 점수(image score)만으로도 이미 코일이 1등이었다 → **원인은 색 판정이 아니라 모델(CLIP)이 "단순한 형태 + 밝은 배경의 사진"과 "코일의 단순한 회색 그림"을 시각적으로 비슷하다고 보는 것**. 이건 실제 사람 사진과 만화 그림을 비교하는 이 프로젝트 방식 자체의 한계로, PRD에도 "결과가 가끔 엉뚱할 수 있다"고 미리 적어둔 부분이다.
- **모델/데이터 문제 아님**: 색·분위기 판정 자체(labels 벡터)는 정상 동작했다(모든 사진에서 사람 판정도 올바르게 person으로 나옴).
- **화면 문제 아님**: 3단계에서 만든 화면(진행률, 스피너, 결과 카드)은 이번 시험과 무관하게 정상 작동했다.

## 추가 기록: 5세대 확장 후 "1세대만 나온다" 문제 (2026-09-23)

1~5세대(649마리)로 데이터를 늘린 뒤에도, 배포된 사이트에서 몇 번 테스트해보니 계속 1세대 포켓몬(코일, 피카츄 등)이 1위로 나왔다. 데이터 자체는 5세대까지 정상적으로 들어있는지, 코드가 실제로 649마리 전체를 계산하는지 먼저 확인했다(729마리 → 세대별 개수 확인, 벡터 값이 서로 다른지 확인 → 문제없음).

**원인 분석**: 10장으로 상위 10위까지 직접 뽑아보니, 실제로는 2~5세대 포켓몬도 근소한 차이(0.001~0.01점)로 상위권에 있었다. 즉 "1세대만 후보에 오르는" 게 아니라, **동점에 가까운 상황에서 1세대(특히 피카츄, 코일처럼 유명한 포켓몬)가 자주 근소하게 이기는 경향**이었다. CLIP은 인터넷의 방대한 텍스트·이미지로 학습되는데, 유명한 포켓몬일수록 학습 데이터에 훨씬 많이 등장했을 가능성이 높아 모델이 그 이름과 이미지를 더 강하게 연결 짓는 것으로 보인다 → **원인은 모델(CLIP)의 유명세 편향, 데이터나 코드 버그 아님**.

**적용한 수정 (센터링 보정)**: `public/matcher.js`에서 649마리 설명글/그림 벡터의 "평균 방향"을 구해서, 사진 벡터와 포켓몬 벡터 양쪽에서 그 평균을 뺀 뒤 비교하도록 바꿨다. 이렇게 하면 "모든 포켓몬과 공통으로 비슷한 정도"(유명세 편향 등)가 상쇄되고, 그 사진만의 특징이 점수에 더 크게 반영된다.

같은 10장으로 다시 시험한 결과 top1 세대 분포:

| | 1세대 | 2세대 | 3세대 | 4세대 | 5세대 |
|---|---|---|---|---|---|
| 보정 전 | 3 | 2 | 4 | 0 | 1 |
| 보정 후 | 3 | 4 | 1 | 0 | 2 |

세대 분포 자체는 원래도 나쁘지 않았지만(1세대만 나온 게 아니었음), 동점에 가까웠던 사진 중 3장(men-3, men-5, women-4)의 1위가 다른 세대로 바뀌었다. 점수 분포도 완전히 달라져서(보정 전 0.36~0.45 → 보정 후 -0.16~0.25), `SIMILARITY_MIN`/`MAX`도 0.2~0.42 → 0~0.25로 다시 조정했다.

**남은 한계**: 센터링을 적용해도 회색 배경 사진(men-1, women-1)은 여전히 코일이 1위였다. 이건 색 보정이나 세대 편향 보정만으로는 완전히 없어지지 않는, CLIP이 실사 사진과 만화 그림을 비교할 때 생기는 근본적인 한계로 보인다.
